## Section 1 — Product Requirements Document (PRD)

### 1.1 Vision

DocLink is Ghana's first multi-specialty telemedicine platform that makes quality healthcare accessible to every Ghanaian — from Accra professionals booking lunchtime dermatology consults to rural patients in Brong-Ahafo dialling in via USSD on feature phones. Patients book video or in-person consultations with verified, Ghana Medical Council–registered doctors, pay via MTN Mobile Money, and receive digital prescriptions directly in the app. By 2029, DocLink has 500,000 registered patients, 1,200 verified doctors, operates across Ghana, and delivers 1 million consultations annually — reducing unnecessary emergency room visits by 40%.

### 2.3 Data Flow Narratives

**1. Phone OTP registration**
Patient enters phone → Supabase Auth calls Africa's Talking `send-otp` → SMS delivered < 15s → patient submits code → JWT issued with `tenant_id` + `role: patient` → `customers` row upserted.

**2. Booking creation (video consultation)**
Patient selects doctor + specialty + slot → `POST /book-consultation` → availability check against `availability_windows` → `INSERT INTO bookings (status='held', held_until=now()+15min, appointment_type='video')` → `EXCLUDE USING gist` fires (409 if doctor busy) → MTN MoMo payment initiated (patient's phone number) → STK push sent to patient's phone.

**3. MoMo payment confirmation**
Patient approves on phone → MTN MoMo sends callback to `POST /confirm-momo` → HMAC-SHA-256 verified → `UPDATE bookings SET status='confirmed'` → Whereby room created (`create-video-room`) → room URLs stored on booking → Africa's Talking SMS sent to patient + doctor with consult link.

**4. USSD booking (feature phone)**
Patient dials `*920*100#` → Africa's Talking routes to `POST /ussd` Edge Function → menu state in `ussd_sessions` table → patient selects specialty → available slots listed → slot selected → phone number used for MoMo payment → booking created.

```sql
-- Notify waitlist on slot opening
CREATE OR REPLACE FUNCTION notify_waitlist()
RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER AS $$
DECLARE
  v_entry waitlist_entries%ROWTYPE;
BEGIN
  IF NEW.status IN ('cancelled', 'no_show')
     AND OLD.status NOT IN ('cancelled', 'no_show') THEN

    SELECT * INTO v_entry
    FROM waitlist_entries
    WHERE branch_id   = NEW.branch_id
      AND tenant_id   = NEW.tenant_id
      AND slot_date   = NEW.starts_at::date
      AND (doctor_id IS NULL OR doctor_id = NEW.doctor_id)
      AND (specialty IS NULL OR specialty = NEW.specialty)
      AND notified_at IS NULL
    ORDER BY created_at ASC
    LIMIT 1;

    IF FOUND THEN
      INSERT INTO automation_jobs (
        tenant_id, booking_id, job_type, payload, scheduled_for, idempotency_key
      ) VALUES (
        NEW.tenant_id, NEW.id,
        'notify_waitlist_patient',
        jsonb_build_object(
          'waitlist_entry_id', v_entry.id,
          'patient_id',        v_entry.patient_id,
          'slot_date',         NEW.starts_at::date,
          'specialty',         NEW.specialty
        ),
        now(),
        'waitlist_' || v_entry.id || '_' || NEW.id
      )
      ON CONFLICT (idempotency_key) DO NOTHING;

      UPDATE waitlist_entries SET notified_at = now() WHERE id = v_entry.id;
    END IF;
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER trg_notify_waitlist
  AFTER UPDATE ON bookings
  FOR EACH ROW EXECUTE FUNCTION notify_waitlist();

-- Track no-show count and apply policy
CREATE OR REPLACE FUNCTION track_patient_no_show()
RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER AS $$
DECLARE
  v_policy  jsonb;
  v_strikes int;
BEGIN
  IF NEW.status = 'no_show' AND OLD.status != 'no_show' THEN
    UPDATE customers
    SET no_show_count = no_show_count + 1
    WHERE id = NEW.patient_id
    RETURNING no_show_count INTO v_strikes;

    SELECT no_show_policy INTO v_policy FROM branches WHERE id = NEW.branch_id;

    IF v_strikes >= (v_policy->>'max_strikes')::int THEN
      UPDATE customers SET require_prepayment = true WHERE id = NEW.patient_id;
    END IF;
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER trg_track_patient_no_show
  AFTER UPDATE ON bookings
  FOR EACH ROW EXECUTE FUNCTION track_patient_no_show();

CREATE MATERIALIZED VIEW branch_kpis AS
SELECT
  b.branch_id,
  b.tenant_id,
  date_trunc('day', b.starts_at)                                       AS kpi_date,
  COUNT(*) FILTER (WHERE b.status = 'completed')                       AS completed_consultations,
  COUNT(*) FILTER (WHERE b.status = 'no_show')                         AS no_show_count,
  COUNT(*) FILTER (WHERE b.status = 'cancelled')                       AS cancellation_count,
  COUNT(*) FILTER (WHERE b.appointment_type = 'video')                 AS video_consultations,
  COUNT(*) FILTER (WHERE b.appointment_type = 'ussd_phone')            AS ussd_consultations,
  COALESCE(SUM(b.fee_ghs) FILTER (WHERE b.status = 'completed'), 0)   AS revenue_ghs,
  now()                                                                 AS refreshed_at
FROM bookings b
GROUP BY b.branch_id, b.tenant_id, date_trunc('day', b.starts_at)
WITH DATA;

CREATE UNIQUE INDEX ON branch_kpis (branch_id, kpi_date);
```

### POST /functions/v1/confirm-momo
**Auth**: HMAC-SHA-256 via `X-Callback-Signature` header (MTN MoMo webhook)
**Purpose**: Confirm MTN MoMo payment; transition `held → confirmed`; create Whereby room

**Request** (MTN MoMo callback payload):
```json
{
  "financialTransactionId": "9123456789",
  "externalId": "doclink_booking_uuid_1722780000",
  "amount": "120",
  "currency": "GHS",
  "payer": { "partyIdType": "MSISDN", "partyId": "233241234567" },
  "status": "SUCCESSFUL",
  "payerMessage": "DocLink consultation",
  "payeeNote": "Dr. Mensah – Dermatology"
}
```

**Transition logic**:
1. Verify `X-Callback-Signature`: `HMAC-SHA-256(rawBody, MTN_MNO_SUBSCRIPTION_KEY)` — reject with 401 on mismatch
2. Assert `status === 'SUCCESSFUL'`; resolve booking by `externalId`
3. `UPDATE bookings SET status='confirmed', payment_status='paid'`
4. Create Whereby room (if `appointment_type='video'`): `POST /meetings` → store `whereby_meeting_id`, `whereby_room_url`, `whereby_host_url` on booking
5. Credit loyalty: 1 point per GH₵10 paid — `INSERT INTO loyalty_transactions ... ON CONFLICT DO NOTHING`
6. Schedule `automation_jobs`: `consult_reminder_24h`, `consult_reminder_1h`, `prescription_reminder`
7. AT SMS to patient: "Your DocLink consult is confirmed. Join at: {whereby_room_url}"
8. AT SMS to doctor: "Consult with {patient_name} at {time}. Join: {whereby_host_url}"

```typescript
async function handleUssd(sessionId: string, phone: string, text: string) {
  const session = await getOrCreateUssdSession(sessionId, phone)
  const inputs = text.split('*')
  const level = inputs.length

  switch (session.menu_state) {
    case 'MAIN':
      if (level === 1 && inputs[0]) {
        await updateUssdSession(sessionId, { menu_state: 'SELECT_SLOT', context: { specialty: inputs[0] } })
        return `CON ${buildSlotMenu(inputs[0])}`
      }
      return `CON Welcome to DocLink\n1. General Practice\n2. Dermatology\n3. Mental Health\n4. Other`

    case 'SELECT_SLOT':
      await updateUssdSession(sessionId, { menu_state: 'CONFIRM', context: { ...session.context, slot_index: inputs[level-1] } })
      return `CON Confirm booking...\n1. Confirm\n2. Cancel`

    case 'CONFIRM':
      if (inputs[level-1] === '1') {
        await createBookingFromUssd(session)
        return `END Booking confirmed! MoMo payment sent. Confirm on your phone.`
      }
      return `END Booking cancelled.`
  }
}
```

## Section 7 — Automation Engine

### pg_cron jobs

```sql
-- Release held slots every minute
SELECT cron.schedule('doclink-release-held-slots', '* * * * *', $$
  UPDATE bookings
  SET status = 'cancelled', cancelled_at = now()
  WHERE status = 'held'
    AND held_until < now();
$$);

-- Mark no-shows 20 minutes after consultation end
SELECT cron.schedule('doclink-mark-noshows', '*/5 * * * *', $$
  UPDATE bookings
  SET status = 'no_show'
  WHERE status IN ('confirmed', 'checked_in')
    AND ends_at < now() - interval '20 minutes';
$$);

-- Refresh branch_kpis every 15 minutes
SELECT cron.schedule('doclink-refresh-kpis', '*/15 * * * *', $$
  REFRESH MATERIALIZED VIEW CONCURRENTLY branch_kpis;
$$);

-- Expire stale USSD sessions every 5 minutes
SELECT cron.schedule('doclink-expire-ussd-sessions', '*/5 * * * *', $$
  DELETE FROM ussd_sessions WHERE expires_at < now();
$$);
```

### Edge Function: confirm-momo (HMAC-SHA-256 verification)

```typescript
const rawBody = await req.text()
const signature = req.headers.get('X-Callback-Signature') ?? ''

// MTN MoMo uses HMAC-SHA-256 with the subscription key
const expectedSig = createHmac('sha256', Deno.env.get('MTN_MNO_SUBSCRIPTION_KEY')!)
  .update(rawBody)
  .digest('hex')

if (signature !== expectedSig) {
  return new Response('Unauthorized', { status: 401 })
}

const payload = JSON.parse(rawBody)
if (payload.status !== 'SUCCESSFUL') {
  // Payment failed: cancel booking, release slot
  await supabase.from('bookings')
    .update({ status: 'cancelled', payment_status: 'failed', cancelled_at: new Date().toISOString() })
    .eq('momo_ref', payload.externalId)
  return new Response('OK', { status: 200 })
}

// Confirm booking
const bookingId = payload.externalId.replace('doclink_', '').split('_')[0]
await supabase.from('bookings')
  .update({ status: 'confirmed', payment_status: 'paid' })
  .eq('id', bookingId)
  .eq('status', 'held')

// Create Whereby video room if video appointment
const booking = await getBooking(bookingId)
if (booking.appointment_type === 'video') {
  const room = await createWherebyRoom({
    meetingName: `DocLink – ${booking.doctor.full_name} × ${booking.patient.full_name}`,
    bookingId,
    startTime: new Date(new Date(booking.starts_at).getTime() - 10 * 60_000).toISOString(),
    endTime: new Date(new Date(booking.ends_at).getTime() + 10 * 60_000).toISOString(),
  })
  await supabase.from('bookings').update({
    whereby_meeting_id: room.meetingId,
    whereby_room_url:   room.roomUrl,
    whereby_host_url:   room.hostRoomUrl,
  }).eq('id', bookingId)
}

// Idempotent loyalty credit: 1 point per GH₵10
const amountGhs = parseFloat(payload.amount)
const points = Math.floor(amountGhs / 10)
await supabase.from('loyalty_transactions').insert({
  tenant_id, account_id: loyaltyAccountId, booking_id: bookingId,
  points_delta: points, reason: 'consultation_payment',
  idempotency_key: `loyalty_${bookingId}_${payload.financialTransactionId}`,
}).onConflict('idempotency_key').ignore()
```

## Assumptions Made

- **Multi-tenancy**: Each clinic network or hospital group is a `tenant`; branches are individual clinics; virtual-only branches (`is_virtual=true`) have no address
- **Auth**: Phone OTP via Africa's Talking is the only auth method; email is optional profile field
- **GMC compliance**: `gmc_number` is mandatory for `role='doctor'`; enforced by DB CHECK constraint; admin verifies legitimacy during onboarding
- **Full consultation fee collected upfront**: `deposit_policy` defaults to 100% at booking for telemedicine; partial deposits configurable per branch for premium specialists
- **Whereby rooms**: Created on `booking.confirmed` event (after MoMo payment); room unlocks 10 min before `starts_at` and expires 10 min after `ends_at`; delete room on cancellation via `deleteWherebyRoom()`
- **USSD sessions**: 90-second TTL enforced by Africa's Talking; stale sessions cleaned by `pg_cron` every 5 minutes; USSD state stored in DB (sufficient at MVP scale)
- **Prescription immutability**: Once issued, `prescription_records` are not editable; if a doctor needs to correct a prescription, they issue a new one with a note referencing the original
- **Medical records privacy**: All files in `medical-records` Storage bucket are private; 15-minute signed URLs served via Edge Function; never returned as public URLs
- **Slot conflict prevention**: `EXCLUDE USING gist` on `(doctor_id, branch_id, tstzrange)` — virtual and in-person bookings on the same doctor block the same slot
- **No-show policy**: 3-strike system via `track_patient_no_show` trigger; after 3 missed appointments, `require_prepayment=true` on customer
- **Idempotency**: All MoMo transactions and loyalty operations use `idempotency_key` UNIQUE; MoMo callback retries are safe
- **MTN MoMo environment**: Platform ships with `MTN_MNO_ENVIRONMENT=sandbox` for testing; production requires MTN business approval process (2-4 weeks)
