> Full system architecture generated by the Kajola skill.

**Platform**: HairBook — consumer-facing beauty marketplace connecting clients with barbershops, salons, and nail technicians across Nigeria
**Market**: Nigeria (NGN) · **Payments**: Paystack (card + bank transfer + USSD) · **Auth**: Phone OTP (Termii) · **Notifications**: WhatsApp Business API + SMS · **Verticals**: Beauty marketplace (consumer discovery + business operations)

## Section 1 — Product Requirements Document (PRD)

### 1.1 Vision

Nigeria has over 500,000 barbershops and salons operating without digital infrastructure — no online booking, no client history, no payout tracking. Clients discover them through word-of-mouth, physical visits, or Instagram DMs; providers lose revenue to no-shows and pay their staff on gut feeling.

HairBook is the marketplace that closes this gap: a two-sided platform where clients discover, book, and pay for beauty services in three taps, and where businesses manage their calendar, staff earnings, client CRM, and walk-in queue from one dashboard.

Success in 3 years: 50,000 active providers (barbershops, salons, nail techs) across Lagos, Abuja, Port Harcourt, and 5 secondary cities; 2M registered customers; ₦4B in monthly GMV processed; Africa's most-trusted beauty brand on social.

### 1.2 Target Personas

### 2.3 Data Flow Narratives

**1. Client discovers and books a barber**
Client opens map → sets location → `GET /providers/search?lat=6.45&lng=3.47&radius_km=5&category=barbershop` → PostGIS `ST_DWithin` query returns sorted `provider_profiles` → client opens profile → views `portfolio_photos` → selects service + barber → `POST /book-slot` (JWT required, phone OTP gate) → EXCLUDE USING gist rejects conflicts with 409 → slot held 15 min → Paystack payment link returned.

**2. Paystack deposit webhook → booking confirmed**
Client pays on Paystack → `POST /webhook/paystack` → HMAC-SHA-512 verified → `bookings.status: held → confirmed` → `record_staff_earnings()` queued → WhatsApp confirmation sent (if opted in) else Termii SMS → Expo push sent → `automation_jobs` inserts 24h + 2h reminder jobs.

**3. Walk-in POS transaction**
Barber opens POS tab in dashboard → enters client name + service → `POST /walkin/checkin` → `walkin_queue` row inserted (status: `in_service`) → barber marks complete → `POST /walkin/complete` → selects payment method (cash/card/transfer/bundle_credit) → `transactions` row inserted → `record_staff_earnings()` called → `walkin_queue.status: completed`.

**4. Staff commission payout**
Business owner opens Staff → Payouts → `GET /staff/{id}/earnings?week=2026-W30` → query `staff_earnings WHERE staff_id = ? AND status = 'approved'` → total returned → owner confirms payout → `POST /staff/{id}/payout` → `wallet_transactions` debit for platform, credit for staff record → `staff_earnings.status: paid`.

CREATE OR REPLACE FUNCTION notify_waitlist_on_cancellation()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
  IF NEW.status IN ('cancelled', 'no_show') AND OLD.status NOT IN ('cancelled', 'no_show') THEN
    INSERT INTO automation_jobs (job_type, payload, idempotency_key)
    VALUES (
      'waitlist.check',
      jsonb_build_object('booking_id', NEW.id, 'branch_id', NEW.branch_id, 'service_id', NEW.service_id, 'starts_at', NEW.starts_at),
      'waitlist-' || NEW.id
    ) ON CONFLICT (idempotency_key) DO NOTHING;
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER trg_notify_waitlist
AFTER UPDATE ON bookings FOR EACH ROW EXECUTE FUNCTION notify_waitlist_on_cancellation();

RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
  UPDATE provider_profiles SET portfolio_count = (
    SELECT COUNT(*) FROM portfolio_photos WHERE provider_id = COALESCE(NEW.provider_id, OLD.provider_id)

CREATE OR REPLACE FUNCTION update_staff_rating()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
BEGIN
  UPDATE staff SET
    rating = (SELECT ROUND(AVG(rating)::numeric, 2) FROM reviews WHERE staff_id = NEW.staff_id AND is_visible),
    review_count = (SELECT COUNT(*) FROM reviews WHERE staff_id = NEW.staff_id AND is_visible)
  WHERE id = NEW.staff_id;

  UPDATE provider_profiles SET
    avg_rating = (SELECT ROUND(AVG(r.rating)::numeric, 2) FROM reviews r WHERE r.staff_id = NEW.staff_id AND is_visible),
    review_count = (SELECT COUNT(*) FROM reviews WHERE staff_id = NEW.staff_id AND is_visible)
  WHERE entity_type = 'staff' AND entity_id = NEW.staff_id;

  RETURN NEW;
END;
$$;

CREATE TRIGGER trg_update_staff_rating
AFTER INSERT OR UPDATE ON reviews FOR EACH ROW EXECUTE FUNCTION update_staff_rating();

-- ─────────────────────────────────────────────────────────────
-- Branch KPIs (materialised view)
-- ─────────────────────────────────────────────────────────────
CREATE MATERIALIZED VIEW branch_kpis AS
SELECT
  b.id                                                    AS branch_id,
  b.business_id,
  b.tenant_id,
  COUNT(bk.id) FILTER (WHERE bk.status = 'completed'
    AND bk.starts_at >= CURRENT_DATE - 30)               AS bookings_30d,
  COUNT(bk.id) FILTER (WHERE bk.status = 'no_show'
    AND bk.starts_at >= CURRENT_DATE - 30)               AS no_shows_30d,
  COALESCE(SUM(bk.total_amount) FILTER (WHERE bk.status = 'completed'
    AND bk.starts_at >= CURRENT_DATE - 30), 0)           AS revenue_30d_kobo,
  COUNT(DISTINCT bk.customer_id) FILTER (WHERE bk.starts_at >= CURRENT_DATE - 30) AS unique_clients_30d,
  ROUND(AVG(s.rating), 2)                                AS avg_staff_rating,
  COUNT(wq.id) FILTER (WHERE wq.status = 'completed'
    AND wq.arrived_at >= CURRENT_DATE - 30)              AS walkins_30d,
  now()                                                  AS refreshed_at
FROM branches b
LEFT JOIN bookings bk ON bk.branch_id = b.id
LEFT JOIN staff s     ON s.branch_id = b.id
LEFT JOIN walkin_queue wq ON wq.branch_id = b.id
GROUP BY b.id, b.business_id, b.tenant_id;

## Section 7 — Automation Engine

### 7.1 Event Catalogue

| Event | Trigger | Payload | Action |
|---|---|---|---|
| `booking.held` | POST /book-slot success | booking_id, customer_id, held_until | Log audit; start 15-min hold timer |
| `booking.confirmed` | confirm-payment webhook | booking_id, amount | WhatsApp confirmation (fallback SMS); Expo push; schedule 24h + 2h reminders |
| `booking.checked_in` | Staff marks checked_in | booking_id | Start SLA clock; notify staff dashboard |
| `booking.completed` | Staff marks completed | booking_id | `record_staff_earnings()`; credit loyalty points; trigger rating prompt 2h later |
| `booking.cancelled` | Any cancellation | booking_id, reason | Notify waitlist; process refund if deposit paid; decrement held_until slot |
| `booking.no_show` | pg_cron mark_no_shows | booking_id | Increment customer no_show_count; apply policy (block if ≥ 2); notify waitlist |
| `payment.confirmed` | Paystack charge.success | booking_id, amount | Transition held → confirmed; update deposit_paid |
| `waitlist.check` | notify_waitlist_on_cancellation trigger | branch_id, service_id | Query waitlist_entries; SMS + WhatsApp first match |
| `reminder.24h` | Scheduled (automation_jobs) | booking_id | WhatsApp reminder (fallback SMS Termii) |
| `reminder.2h` | Scheduled (automation_jobs) | booking_id | WhatsApp reminder (fallback SMS) |
| `review.prompt` | 2h after booking.completed | booking_id, customer_id | Push notification + WhatsApp: "Rate your experience" |
| `bundle.redeemed` | redeem_bundle_credit() | credit_id, sessions_remaining | Push: "You have N sessions remaining in your bundle" |
| `loyalty.tier_upgrade` | After points credited | account_id, new_tier | WhatsApp + push: "You've reached Gold tier 🎉" |
| `rebooking.nudge` | pg_cron daily | customer_id, last_booking_date | WhatsApp: "Time for your next cut?" — fires on median rebooking interval |

### 7.2 automation_jobs Schema

The `automation_jobs` table (see Section 3) drives all async work. Worker polls `status = 'pending'` every minute.

### 7.3 Cron Jobs

| Job | Schedule | Action |
|---|---|---|
| `release-held-slots` | Every 1 min | Cancel bookings where `status='held' AND held_until < now()` |
| `mark-no-shows` | Every 5 min | Transition to `no_show` where booking ended 30+ min ago |
| `refresh-branch-kpis` | Every 15 min | `REFRESH MATERIALIZED VIEW CONCURRENTLY branch_kpis` |
| `expire-bundle-credits` | Daily 01:00 | Set `status='expired'` on overdue bundle_credits |
| `expire-waitlist` | Daily 03:00 | Delete expired waitlist_entries |
| `send-reminders` | Every 30 min | Process `automation_jobs WHERE job_type LIKE 'reminder.%'` |
| `rebooking-nudges` | Daily 10:00 | For clients whose last booking was ≥ median interval days ago |

### 7.5 AI Operations

- `no_show_probability`: logistic model trained on `(no_show_count, time_of_day, advance_booking_days, is_deposit_paid)`; stored on each booking at insert time
- **Re-booking nudge**: per-service median rebooking interval computed monthly from completed bookings; daily cron fires WhatsApp nudge for clients overdue by > 10%
- **Smart scheduling**: "earliest available" API returns slot minimising idle gaps rather than first chronological slot (bin-packing heuristic)

## Assumptions Made

- **Stack**: Default stack applied (Next.js 14, Expo 51, Supabase, Paystack, Termii, WhatsApp Cloud API) — no stack deviations specified
- **Target market**: Nigeria assumed primary; Lagos as launch city; Paystack NGN as primary payment; Termii as SMS provider; WhatsApp Cloud API (Meta) for rich messaging

- **Consumer vs business app**: Two separate app experiences (consumer Expo + business Next.js) — a combined app can be built post-MVP
- **Walk-in POS**: Cash tracking is ledger-only (no cash drawer hardware integration assumed); card and transfer via Paystack terminal or manual confirmation
- **Portfolio bucket**: `portfolios` bucket set to PRIVATE; all images served via signed URLs with 1h TTL; no CDN in MVP (added at 100k users)
