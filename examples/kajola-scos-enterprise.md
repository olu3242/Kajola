## Section 1 — Product Requirements Document

### 1.1 Vision

Africa's ₦15 trillion+ service economy — beauty, wellness, healthcare, home services, logistics, hospitality — runs almost entirely on informal WhatsApp chains, phone calls, and cash. No single platform owns the end-to-end service commerce lifecycle across the continent. Kajola SCOS is that platform: an enterprise operating system that powers every layer of service commerce — consumer discovery, intelligent booking, multi-provider payments, post-service gratuity, loyalty, franchise management, and a full relationship economy. In five years, Kajola SCOS is the default runtime for 100,000 service businesses in 12 African countries, processing ₦500B+ in annual GMV, with a platform ecosystem of franchise networks, enterprise clients, and independent providers all operating on one unified infrastructure.

### 2.3 Data Flow Narratives

#### Flow 1: Tenant-Aware Customer Registration
1. Customer enters +234 (NG) / +254 (KE) / +233 (GH) phone number in app
2. App calls `POST /auth/send-otp` — Edge Function detects country code, routes to Termii (NG/GH) or Africa's Talking (KE)
3. OTP SMS delivered; customer enters code in app
4. `POST /auth/verify-otp` — Edge Function verifies hash, calls `supabase.auth.admin.createUser`, embeds `tenant_id` (country tenant) + `role = 'customer'` in JWT claims
5. `profiles` + `customer_profiles` rows created; `current_user_tenant_id()` resolves to country tenant for all subsequent RLS

#### Flow 2: SORF Booking Lifecycle + WRF Audit Trail
1. Customer discovers "Hair Braiding" near Ikeja → `GET /providers/search?q=braiding&lat=6.60&lng=3.35&radius_km=5`
2. Selects provider Taiwo Cuts → books slot: `POST /book-slot` — Edge Function: JWT verify → tenant resolve → RBAC check → availability check → EXCLUDE USING gist → `booking` created (`status: held`, `held_until = now() + 15 min`) → `audit_logs` row emitted
3. Paystack STK-style charge initiated: `POST /payments/initiate` — idempotency_key = `booking-{id}-deposit`
4. Paystack webhook `POST /webhooks/paystack` — HMAC-SHA-512 verified → booking `held → confirmed` → `audit_logs` row → `platform_metrics` latency emitted
5. Automation fires `booking.confirmed`: Termii SMS to customer + staff; WhatsApp confirmation to customer
6. 24h cron: reminder SMS; 2h cron: reminder push notification
7. Staff taps "Done" → `PATCH /bookings/:id/complete` → `in_progress → completed` → gratuity prompt fires
8. Customer tips ₦500 via separate Paystack charge → `gratuities` row → 100% to provider → `recognition.badge_awarded` event if staff enters top-10 weekly leaderboard
9. Loyalty points credited → `loyalty_transactions` idempotent (key: `loyalty-{booking-id}-earn`)
10. 28-day AI nudge: `rebook-{customer-id}-{service-id}` automation job → WhatsApp nudge

#### Flow 3: Multi-Country Payment Routing
- **Nigeria request**: country_code = `NG` → `tenants.config.payment_providers = ["paystack", "flutterwave"]` → route to Paystack → charge in NGN
- **Kenya request**: country_code = `KE` → `tenants.config.payment_providers = ["mpesa_daraja", "flutterwave"]` → route to Daraja C2B STK Push → collect in KES
- **Ghana request**: country_code = `GH` → `tenants.config.payment_providers = ["mtn_momo", "flutterwave"]` → route to MTN MoMo → collect in GHS
- **Fallback**: any provider webhook timeout → retry via Flutterwave for that transaction; `automation_jobs` handles retry with 3 attempts, exponential back-off

#### Flow 4: Gratuity Capture
1. `booking.completed` event fires → automation job `gratuity_prompt` schedules 2-min delay
2. Customer app shows "Tip your provider?" screen with preset amounts (₦100 / ₦200 / ₦500 / Custom)
3. Customer selects ₦500 → `POST /gratuities` — separate Paystack charge (not included in booking amount); idempotency_key = `gratuity-{booking-id}`
4. On payment success: `gratuities` row created; `payment_type = 'gratuity'`; full ₦500 credited to provider wallet — platform takes 0% commission
5. `gratuity.received` event: Termii SMS to provider "Taiwo, you received a ₦500 tip from a customer! Keep up the great work."
6. Staff leaderboard materialised view refreshed daily; if provider enters top-5, `recognition.badge_awarded` event fires

### Helper Functions

```sql
-- Returns the tenant_id from the current JWT claims
CREATE OR REPLACE FUNCTION current_user_tenant_id()
RETURNS uuid LANGUAGE sql STABLE AS $$
  SELECT COALESCE(
    (auth.jwt() -> 'app_metadata' ->> 'tenant_id')::uuid,
    NULL
  )
$$;

-- Returns true if the current user has super_admin or platform_admin role
CREATE OR REPLACE FUNCTION is_super_admin()
RETURNS boolean LANGUAGE sql STABLE AS $$
  SELECT COALESCE(
    (auth.jwt() -> 'app_metadata' ->> 'role') IN ('super_admin', 'platform_admin'),
    false
  )
$$;

-- Auto-update updated_at on any table
CREATE OR REPLACE FUNCTION update_updated_at()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  NEW.updated_at := now();
  RETURN NEW;
END;
$$;
```

```sql
FROM branches br
LEFT JOIN bookings b ON b.branch_id = br.id
LEFT JOIN reviews r ON r.booking_id = b.id
WHERE b.starts_at >= now() - interval '90 days'
GROUP BY br.id, br.tenant_id, br.name, br.city, date_trunc('day', b.starts_at);
```

```sql
-- Process pending automation jobs
SELECT cron.schedule('process-automation-jobs', '* * * * *',
  $$SELECT process_pending_jobs()$$);

-- Refresh branch KPIs every 15 min
SELECT cron.schedule('refresh-branch-kpis', '*/15 * * * *',
  $$REFRESH MATERIALIZED VIEW CONCURRENTLY branch_kpis$$);

-- Refresh staff leaderboard daily at midnight
SELECT cron.schedule('refresh-staff-leaderboard', '0 0 * * *',
  $$REFRESH MATERIALIZED VIEW CONCURRENTLY staff_leaderboard$$);

-- Send 24h booking reminders
SELECT cron.schedule('send-24h-reminders', '0 * * * *',
  $$UPDATE automation_jobs SET status = 'pending', next_run_at = now()
    WHERE job_type = 'reminder.24h' AND status = 'pending' AND next_run_at <= now()$$);

-- Weekly payout batch — Mondays 08:00 WAT
SELECT cron.schedule('weekly-payout-batch', '0 7 * * 1',
  $$INSERT INTO automation_jobs(tenant_id, job_type, payload, idempotency_key)
    SELECT t.id, 'payout.batch_initiate', '{}',
      'payout-batch-' || to_char(now(), 'YYYY-WW') || '-' || t.id
    FROM tenants t WHERE t.is_active = true
    ON CONFLICT (idempotency_key) DO NOTHING$$);
```

## Section 7 — Automation Engine

### 7.1 Event Catalogue

| Event Name | Trigger | Handler Action | Idempotency Key Pattern |
|---|---|---|---|
| `booking.held` | Booking created `status = held` | Start 15-min hold timer; emit audit log (WRF #6) | `booking-{id}-held` |
| `booking.confirmed` | Deposit paid; status → `confirmed` | Termii SMS (NG/GH) or Africa's Talking SMS (KE) to customer + staff; WhatsApp if opted-in; emit audit + metrics | `booking-{id}-confirmed` |
| `booking.checked_in` | Staff marks checked-in | Log check-in time; push to provider app; emit audit | `booking-{id}-checkin` |
| `booking.completed` | Staff marks completed | Initiate balance charge or STK Push; credit loyalty (idempotent); schedule gratuity prompt (2-min delay); trigger review SMS (30-min delay); emit audit + metrics | `booking-{id}-completed` |
| `booking.cancelled` | Status → `cancelled` | Evaluate refund per cancellation_policy; initiate refund; notify waitlist via DB trigger; emit audit | `booking-{id}-cancelled` |
| `booking.no_show` | pg_cron: no check-in 30+ min post-start | Increment `no_show_count`; apply no_show_policy (prepayment flag if ≥ threshold from tenants.config); notify branch manager; emit audit | `booking-{id}-no-show` |
| `booking.disputed` | Dispute raised | Freeze payout_ledger entry; create dispute record; notify enterprise manager | `booking-{id}-disputed` |
| `payment.confirmed` | Paystack/Daraja/MoMo webhook success | Update payment_transactions + booking; emit audit; emit latency metric | `{provider}-{tx-id}` |
| `payment.failed` | Webhook failure | Release slot hold; notify customer with retry link via Termii/AT; emit audit | `{provider}-{tx-id}-fail` |
| `gratuity.received` | gratuities row created | Termii SMS to provider: "You received a ₦{amount} tip!"; emit recognition event if top-5 branch leaderboard | `gratuity-{id}-notify` |
| `recognition.badge_awarded` | Leaderboard rank ≤ 5 | WhatsApp to provider: badge + celebration message; update recognition_events | `recognition-{staff-id}-{week}` |
| `waitlist.notified` | DB trigger on cancellation | SMS to next waitlist entry; 15-min acceptance window from tenants.config | `waitlist-{entry-id}-notify` |
| `loyalty.credited` | `booking.completed` | Insert loyalty_transactions (idempotent); check tier upgrade; SMS if tier upgraded | `loyalty-{booking-id}-earn` |
| `reminder.24h` | pg_cron 24h before `starts_at` | Termii SMS (NG/GH) / AT SMS (KE): "Your appointment is tomorrow…"; push notification | `reminder-{booking-id}-24h` |
| `reminder.2h` | pg_cron 2h before `starts_at` | SMS: 2h reminder + branch address or Maps link | `reminder-{booking-id}-2h` |
| `ai.noshow_risk` | Daily cron 22:00 local | Score next-day bookings; flag > 60%; SMS alert to branch manager | `ai-noshow-{date}-{booking-id}` |
| `ai.rebook_nudge` | Median re-booking interval post-completion | WhatsApp nudge with last provider name; respect opt-out flag | `rebook-{customer-id}-{service-id}` |
| `payout.batch_initiate` | pg_cron Monday 07:00 UTC | Batch all pending payout_ledger entries; initiate Paystack Transfer (NG), M-Pesa B2C (KE), MoMo disbursement (GH) | `payout-batch-{YYYY-WW}-{tenant-id}` |
| `customer.milestone.10_bookings` | lifetime_booking_count crosses 10 | Loyalty bonus + badge + WhatsApp celebration | `milestone-{customer-id}-10-bookings` |

### 7.3 WRF Audit Emission (Every State Transition)

Every Edge Function that mutates state MUST call `wrf-audit-emit`:
```typescript
// In every mutation Edge Function:
await emitAudit({
  tenantId,
  actorId: userId,
  action: 'booking.confirmed',
  entityType: 'booking',
  entityId: bookingId,
  beforeState: { status: 'held' },
  afterState: { status: 'confirmed', deposit_paid: true },
  ipAddress: req.headers.get('x-forwarded-for'),
});
// And emit latency metric:
await emitMetric({ tenantId, metricName: 'booking.confirm.latency_ms', metricValue: elapsed, dimensions: { country: 'NG', engine: 'booking' } });
```

### 7.4 Webhook Security

All payment webhooks:
1. Verify HMAC before any processing
2. Return 200 immediately; process asynchronously via automation_jobs
3. Idempotency key = `{provider}:{event_id}`
4. Log raw payload to `webhook_logs` before processing

### 12.3 Data Isolation Model

**Every domain table has a `tenant_id` column** that references `tenants.id`. RLS policies uniformly enforce:
```sql
USING (tenant_id = current_user_tenant_id() OR is_super_admin())
```

The `current_user_tenant_id()` function extracts `tenant_id` from the Supabase JWT `app_metadata` claim — set at sign-up based on the user's phone country code. No application-level join can bypass this: the DB enforces isolation before any query resolves.

**Cross-tenant access rules:**
- `role = 'customer'` or `'staff'`: access only to their own country tenant
- `role = 'franchise_owner'`: access to their franchise + all child branches within the same country tenant
- `role = 'enterprise_manager'`: access to their enterprise tenant + all franchise/branch children
- `role = 'platform_admin'` or `'super_admin'`: `is_super_admin()` returns true; bypasses RLS; access via service role only (never from client apps)

### 12.4 Cross-tenant Analytics

Platform-level materialised views — accessible only via `role = 'platform_admin'` using service role key:

```sql
-- Platform GMV by country (refresh daily)
CREATE MATERIALIZED VIEW platform_gmv_by_country AS
SELECT
  t.country_code,
  t.currency_code,
  date_trunc('day', b.completed_at) AS gmv_date,
  COUNT(b.id) AS completed_bookings,
  SUM(b.total_amount_kobo) AS gross_gmv_kobo,
  SUM(pl.platform_commission_kobo) AS platform_revenue_kobo
FROM bookings b
JOIN tenants t ON b.tenant_id = t.id
JOIN payout_ledger pl ON pl.booking_id = b.id
WHERE b.booking_status = 'completed'
GROUP BY t.country_code, t.currency_code, date_trunc('day', b.completed_at);

-- Platform booking health (refresh every 6 hours)
CREATE MATERIALIZED VIEW platform_booking_health AS
SELECT
  t.country_code,
  t.id AS tenant_id,
  date_trunc('week', b.created_at) AS health_week,
  COUNT(b.id) AS total_bookings,
  COUNT(b.id) FILTER (WHERE b.booking_status = 'completed') AS completed,
  COUNT(b.id) FILTER (WHERE b.booking_status = 'no_show') AS no_shows,
  COUNT(b.id) FILTER (WHERE b.booking_status = 'disputed') AS disputes,
  ROUND(COUNT(b.id) FILTER (WHERE b.booking_status = 'no_show')::numeric /
    NULLIF(COUNT(b.id), 0) * 100, 2) AS no_show_rate_pct
FROM bookings b
JOIN tenants t ON b.tenant_id = t.id
GROUP BY t.country_code, t.id, date_trunc('week', b.created_at);

-- Provider growth by country (refresh weekly)
CREATE MATERIALIZED VIEW platform_provider_growth AS
SELECT
  t.country_code,
  date_trunc('week', pp.created_at) AS growth_week,
  COUNT(pp.id) AS new_providers
FROM provider_profiles pp
JOIN tenants t ON pp.tenant_id = t.id
GROUP BY t.country_code, date_trunc('week', pp.created_at);
```
