## Section 1 — Product Requirements Document (PRD)

### 1.1 Vision

PawPerfect is Nigeria's first integrated pet care platform — combining grooming appointments, veterinary consultations, and vaccine tracking in one mobile-first app. Pet owners in Lagos and Abuja no longer navigate unverified vet clinics or unreliable groomers; PawPerfect brings verified professionals, transparent pricing, and a digital health passport for every pet to a single platform. By 2029, PawPerfect operates in 5 Nigerian cities, has 50,000 registered pets on its health passport, and processes ₦500M in annual GMV across grooming and veterinary services.

### 2.3 Data Flow Narratives

**1. Phone OTP registration**
Owner enters phone → Supabase Auth calls Termii `send-otp` → SMS delivered < 15s → owner submits OTP → Supabase verifies → JWT issued with `tenant_id` + `role: customer` → `customers` row upserted → owner adds first pet profile.

**2. Booking creation**
Owner selects pet + service (grooming/vet) + staff + slot → `POST /book-appointment` → availability check against `availability_windows` + `availability_overrides` → `INSERT INTO bookings (status='held', held_until=now()+15min)` → `EXCLUDE USING gist` fires (409 if staff busy) → Paystack transaction initialized for deposit → payment URL returned.

**3. Payment and confirmation**
Owner pays → Paystack `charge.success` → `POST /confirm-payment` → HMAC-SHA-512 verified → `UPDATE bookings SET status='confirmed'` → loyalty points credited (idempotent) → SMS reminders scheduled in `automation_jobs`.

**4. Vaccine record issuance**
Vet completes consultation → `POST /issue-vaccine` → `INSERT INTO vaccine_records` → PDF certificate uploaded to private Storage → `automation_jobs` row inserted for vaccine due alert at `next_due_at - 7 days` → owner receives SMS: "Vaccine certificate ready in app".

-- Notify waitlist when a slot opens up
CREATE OR REPLACE FUNCTION notify_waitlist()
RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER AS $$
DECLARE
  v_entry waitlist_entries%ROWTYPE;
BEGIN
  IF NEW.status IN ('cancelled', 'no_show')
     AND OLD.status NOT IN ('cancelled', 'no_show') THEN

    SELECT * INTO v_entry
    FROM waitlist_entries
    WHERE branch_id   = NEW.branch_id
      AND tenant_id   = NEW.tenant_id
      AND slot_date   = NEW.starts_at::date
      AND (staff_id IS NULL OR staff_id = NEW.staff_id)
      AND notified_at IS NULL
    ORDER BY created_at ASC
    LIMIT 1;

    IF FOUND THEN
      INSERT INTO automation_jobs (
        tenant_id, booking_id, job_type, payload, scheduled_for, idempotency_key
      ) VALUES (
        NEW.tenant_id, NEW.id,
        'notify_waitlist_customer',
        jsonb_build_object(
          'waitlist_entry_id', v_entry.id,
          'customer_id',       v_entry.customer_id,
          'pet_id',            v_entry.pet_id,
          'branch_id',         NEW.branch_id,
          'slot_date',         NEW.starts_at::date
        ),
        now(),
        'waitlist_' || v_entry.id || '_' || NEW.id
      )
      ON CONFLICT (idempotency_key) DO NOTHING;

      UPDATE waitlist_entries SET notified_at = now() WHERE id = v_entry.id;
    END IF;
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER trg_notify_waitlist
  AFTER UPDATE ON bookings
  FOR EACH ROW EXECUTE FUNCTION notify_waitlist();

-- Track no-show count and apply policy
CREATE OR REPLACE FUNCTION track_customer_no_show()
RETURNS trigger LANGUAGE plpgsql SECURITY DEFINER AS $$
DECLARE
  v_policy  jsonb;
  v_strikes int;
BEGIN
  IF NEW.status = 'no_show' AND OLD.status != 'no_show' THEN
    UPDATE customers
    SET no_show_count = no_show_count + 1
    WHERE id = NEW.customer_id
    RETURNING no_show_count INTO v_strikes;

    SELECT no_show_policy INTO v_policy FROM branches WHERE id = NEW.branch_id;

    IF v_strikes >= (v_policy->>'max_strikes')::int THEN
      UPDATE customers SET require_prepayment = true WHERE id = NEW.customer_id;
    END IF;
  END IF;
  RETURN NEW;
END;
$$;

CREATE TRIGGER trg_track_customer_no_show
  AFTER UPDATE ON bookings
  FOR EACH ROW EXECUTE FUNCTION track_customer_no_show();

CREATE MATERIALIZED VIEW branch_kpis AS
SELECT
  b.branch_id,
  b.tenant_id,
  date_trunc('day', b.starts_at)                                     AS kpi_date,
  COUNT(*) FILTER (WHERE b.status = 'completed')                     AS completed_bookings,
  COUNT(*) FILTER (WHERE b.status = 'no_show')                       AS no_show_count,
  COUNT(*) FILTER (WHERE b.status = 'cancelled')                     AS cancellation_count,
  COUNT(*) FILTER (WHERE b.service_type LIKE 'grooming%')            AS grooming_bookings,
  COUNT(*) FILTER (WHERE b.service_type LIKE 'vet%')                 AS vet_bookings,
  COALESCE(SUM(b.price_ngn) FILTER (WHERE b.status = 'completed'), 0) AS revenue_ngn,
  now()                                                               AS refreshed_at
FROM bookings b
GROUP BY b.branch_id, b.tenant_id, date_trunc('day', b.starts_at)
WITH DATA;

CREATE UNIQUE INDEX ON branch_kpis (branch_id, kpi_date);

### POST /functions/v1/confirm-payment
**Auth**: `x-paystack-signature` HMAC-SHA-512
**Purpose**: Transition booking `held → confirmed`; credit loyalty points; schedule reminders

**Transition logic**:
1. Verify: `HMAC-SHA-512(rawBody, PAYSTACK_SECRET_KEY)` against `x-paystack-signature` header
2. Resolve booking by `metadata.booking_id`; assert `status='held'` and `held_until > now()`
3. `UPDATE bookings SET status='confirmed', payment_status='paid'`
4. Credit loyalty points: 1 point per ₦100 — `INSERT INTO loyalty_transactions ... ON CONFLICT (idempotency_key) DO NOTHING`
5. Schedule `automation_jobs`: `appointment_reminder_24h`, `appointment_reminder_2h`
6. Return `200 OK`

## Section 7 — Automation Engine

### pg_cron jobs

```sql
-- Release held slots every minute
SELECT cron.schedule('pawperfect-release-held-slots', '* * * * *', $$
  UPDATE bookings
  SET status = 'cancelled', cancelled_at = now()
  WHERE status = 'held'
    AND held_until < now();
$$);

-- Mark no-shows 30 minutes after appointment should have started
SELECT cron.schedule('pawperfect-mark-noshows', '*/5 * * * *', $$
  UPDATE bookings
  SET status = 'no_show'
  WHERE status IN ('confirmed', 'checked_in')
    AND ends_at < now() - interval '30 minutes';
$$);

-- Refresh branch_kpis every 15 minutes
SELECT cron.schedule('pawperfect-refresh-kpis', '*/15 * * * *', $$
  REFRESH MATERIALIZED VIEW CONCURRENTLY branch_kpis;
$$);

-- Update vaccine status to 'overdue' daily at 08:00
SELECT cron.schedule('pawperfect-mark-overdue-vaccines', '0 8 * * *', $$
  UPDATE vaccine_records
  SET status = 'overdue'
  WHERE status = 'issued'
    AND next_due_at < now();
$$);
```

### Automation job types

| Job type | Trigger | Payload | Action |
|---|---|---|---|
| `appointment_reminder_24h` | booking confirmed | booking_id, customer_phone, pet_name, starts_at | Termii SMS: "Reminder: Bruno's grooming at PawPerfect tomorrow at {time}" |
| `appointment_reminder_2h` | booking confirmed | booking_id, customer_phone, pet_name | Termii SMS: "Bruno's appointment is in 2 hours. Please arrive 5 min early." |
| `notify_waitlist_customer` | booking cancelled/no-show | waitlist_entry_id, customer_id | Termii SMS: "A slot opened at PawPerfect on {date}. Book now: {link}" |
| `vaccine_due_reminder` | vaccine record issued | pet_id, vaccine_name, owner_phone, next_due_at | Termii SMS at `next_due_at - 7 days`: "Bruno's {vaccine} is due in 7 days. Book a vet visit: {link}" |
| `loyalty_points_awarded` | payment confirmed | customer_id, points | Termii SMS: "You earned {N} PawPerfect points. Balance: {total}" |
| `certificate_ready` | vaccine record issued | booking_id, owner_phone, pet_name | Termii SMS: "Bruno's vaccine certificate is ready. View in app: {link}" |

### Edge Function: confirm-payment key logic

```typescript
const rawBody = await req.text()
const signature = req.headers.get('x-paystack-signature') ?? ''
const expected = createHmac('sha512', Deno.env.get('PAYSTACK_SECRET_KEY')!)
  .update(rawBody)
  .digest('hex')

if (signature !== expected) {
  return new Response('Unauthorized', { status: 401 })
}

const event = JSON.parse(rawBody)
if (event.event !== 'charge.success') return new Response('OK', { status: 200 })

const { booking_id, tenant_id, customer_id } = event.data.metadata

await supabase.from('bookings')
  .update({ status: 'confirmed', payment_status: 'paid' })
  .eq('id', booking_id)
  .eq('status', 'held')
  .eq('tenant_id', tenant_id)

// Idempotent loyalty credit
const amountNgn = event.data.amount / 100
const points = Math.floor(amountNgn / 100)
await supabase.from('loyalty_transactions').insert({
  tenant_id,
  account_id: loyaltyAccountId,
  booking_id,
  points_delta: points,
  reason: 'booking_payment',
  idempotency_key: `loyalty_${booking_id}_${event.data.reference}`,
}).onConflict('idempotency_key').ignore()

// Schedule reminders
const booking = await getBooking(booking_id)
await supabase.from('automation_jobs').insert([
  {
    tenant_id, booking_id,
    job_type: 'appointment_reminder_24h',
    payload: { customer_phone: booking.customer.phone, pet_name: booking.pet.name },
    scheduled_for: new Date(new Date(booking.starts_at).getTime() - 24 * 3600_000).toISOString(),
    idempotency_key: `reminder_24h_${booking_id}`,
  },
  {
    tenant_id, booking_id,
    job_type: 'appointment_reminder_2h',
    payload: { customer_phone: booking.customer.phone, pet_name: booking.pet.name },
    scheduled_for: new Date(new Date(booking.starts_at).getTime() - 2 * 3600_000).toISOString(),
    idempotency_key: `reminder_2h_${booking_id}`,
  },
]).onConflict('idempotency_key').ignore()
```

## Assumptions Made

- **Multi-tenancy**: Each PawPerfect clinic operator (franchise or independent) is a `tenant`; branches are individual clinic locations; RLS enforces strict data isolation across tenants
- **Auth**: Phone OTP via Termii is the only auth method; email is optional profile field only
- **VCNV compliance**: Vets must have a `vcnv_number` populated; DB constraint enforces this at INSERT; admin verifies during onboarding
- **Pet ownership**: A pet belongs to one `owner_id` (customer); transferring ownership requires admin action
- **Health notes are immutable**: Once written, `health_notes` rows cannot be updated or deleted; corrections are written as new notes referencing the original
- **Health records are private**: All documents in `pet-records` Storage bucket are served via 15-minute signed URLs only; never public URLs
- **Vaccine status transitions**: `issued → overdue` is handled by daily pg_cron job; `issued → revoked` is manual admin action only
- **Slot conflict prevention**: `EXCLUDE USING gist` on `(staff_id, branch_id, tstzrange)` prevents double-booking at DB level; app-layer checks are advisory only
- **Deposit policy**: 30% deposit at booking via `deposit_policy` jsonb on `branches`; configurable per branch
- **No-show policy**: 3-strike system on `no_show_policy` jsonb; 3rd strike auto-sets `require_prepayment=true` on customer via `track_customer_no_show` trigger
- **Idempotency**: All payment and loyalty operations use `idempotency_key` UNIQUE constraint; Paystack webhook retries are safe
- **Grooming photos**: Stored in private `grooming-photos` bucket; owner sees photos via signed URLs in app; not shared publicly
