# FitBook — Gym & Fitness Class Booking Platform (Nigeria)

> Generated by the Kajola skill · Nigeria · Paystack Recurring · Termii · SORF capacity model

**Prompt used:**
> Design a multi-location gym and fitness class booking platform for Nigeria called FitBook. Members browse and enroll in scheduled group classes (yoga, HIIT, spinning, pilates) or book 1:1 personal training sessions. Gym franchises manage multiple locations and trainers. Members subscribe monthly via Paystack recurring billing (unlimited classes) or buy class packs (10 classes, prepaid). QR code check-in at gym gate. No-show without 2-hour notice loses one class credit. Trainers set their own availability. Loyalty FitPoints earned per session. Full system architecture.

---

## Assumptions Made

- Primary market: Nigeria (NGN); all prices in Naira
- Authentication: Phone OTP via Termii; no email required
- Payments: Paystack for deposits, class packs, and monthly membership subscriptions (Paystack Recurring API)
- QR check-in: unique `check_in_code` UUID printed on member pass; scanned at gym reception desk
- Class enrollment: capacity-constrained (multiple members per class) — distinct from 1:1 appointment booking
- 1:1 personal training: uses EXCLUDE USING gist constraint on trainer schedule (single-occupancy slot)
- No-show policy: < 2h notice = 1 class credit deducted; 3+ no-shows = require prepayment
- Membership types: `unlimited` (₦15,000/month) · `class_pack_10` (10 credits, ₦22,000) · `drop_in` (₦3,500/class)
- SORF 9-state booking lifecycle applied to personal training slots; class enrollments use `class_enrollment_status`
- Stack: Next.js 14 + Expo 51 + Supabase + Paystack + Termii

### 2.3 Data Flow Narratives

**Flow 1 — Member phone OTP registration**
1. Member enters `+2348012345678` on Expo app
2. App calls `POST /send-otp` → Termii `send-otp` API
3. Member enters OTP → `POST /verify-otp` → Supabase Auth session
4. JWT: `{ tenant_id, role: 'member', sub: user_id }`
5. `member_profiles` row created; `loyalty_accounts` row created with `points_balance: 0`

**Flow 2 — Class enrollment (capacity model)**
1. Member browses class schedule: `GET /class-sessions?branch_id=...&date=2026-08-15`
2. Member selects "Thursday 6am HIIT — 8 spots left"
3. `POST /enroll-class` → Edge Function:
   - Checks `memberships.access_type` — unlimited passes free; class_pack deducts 1 credit; drop_in creates Paystack charge
   - `SELECT enrolled_count FROM class_sessions WHERE id = :id FOR UPDATE`
   - If `enrolled_count >= max_capacity` → 409 Class full
   - INSERT `class_enrollments` row; UPDATE `class_sessions SET enrolled_count = enrolled_count + 1`
   - All within a single DB transaction — DB-level atomicity prevents over-enrollment
4. Member receives Termii SMS: "Enrolled in HIIT with Trainer Seun, Thu 6am at Lekki Branch"

**Flow 3 — Personal training session (SORF hold)**
1. Member selects trainer Seun, 45-min slot Thu 8am
2. `POST /book-pt-session` → insert `pt_bookings` row with `status = held`, `held_until = now() + 15 min`; `EXCLUDE USING gist` prevents double-booking trainer
3. Paystack popup for ₦5,000 deposit (50% of ₦10,000 PT fee)
4. Paystack webhook → HMAC verify → `pt_bookings.status → confirmed`; SMS to member + trainer

**Flow 4 — QR code check-in**
1. Member opens app → "Show QR" → displays `member_profiles.check_in_code` as QR
2. Reception staff scans QR on gym tablet → `POST /check-in { code, branch_id }`
3. Edge Function: validate code, find active enrollment for today at this branch, insert `check_ins` row
4. Class enrollment `status → checked_in`; realtime update on trainer's tablet

```sql
-- Ensure enrolled_count never exceeds max_capacity
CREATE OR REPLACE FUNCTION check_class_capacity()
RETURNS trigger AS $$
BEGIN
  IF (SELECT enrolled_count FROM class_sessions WHERE id = NEW.class_session_id) >=
     (SELECT max_capacity FROM class_sessions WHERE id = NEW.class_session_id) THEN
    RAISE EXCEPTION 'class_full: Class session is at full capacity' USING ERRCODE = '23514';
  END IF;
  UPDATE class_sessions SET enrolled_count = enrolled_count + 1 WHERE id = NEW.class_session_id;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Decrement enrolled_count on cancellation
CREATE OR REPLACE FUNCTION decrement_class_count_on_cancel()
RETURNS trigger AS $$
BEGIN
  IF NEW.status = 'cancelled' AND OLD.status = 'enrolled' THEN
    UPDATE class_sessions SET enrolled_count = GREATEST(0, enrolled_count - 1)
    WHERE id = NEW.class_session_id;
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE OR REPLACE FUNCTION notify_waitlist_on_cancellation()
RETURNS trigger AS $$
BEGIN
  IF NEW.status = 'cancelled' AND OLD.status = 'enrolled' THEN
    INSERT INTO automation_jobs (job_type, payload, idempotency_key)
    VALUES (
      'waitlist.notify',
      jsonb_build_object('class_session_id', NEW.class_session_id),
      'waitlist-' || NEW.class_session_id || '-' || now()::date
    )
    ON CONFLICT (idempotency_key) DO NOTHING;
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE MATERIALIZED VIEW branch_kpis AS
SELECT
  b.id                                                              AS branch_id,
  b.tenant_id,
  b.business_id,
  b.name                                                            AS branch_name,
  count(DISTINCT ce.id)                                             AS total_enrollments_30d,
  count(DISTINCT ce.id) FILTER (WHERE ce.status = 'completed')     AS completed_30d,
  count(DISTINCT ce.id) FILTER (WHERE ce.status = 'no_show')       AS no_shows_30d,
  count(DISTINCT bk.id) FILTER (WHERE bk.status = 'completed')     AS pt_sessions_30d,
  count(DISTINCT m.id)  FILTER (WHERE m.is_active = true)          AS active_members,
  coalesce(sum(pt.amount_kobo) FILTER (WHERE pt.status = 'paid'), 0) AS gmv_kobo_30d
FROM branches b
LEFT JOIN class_sessions cs ON cs.branch_id = b.id
  AND cs.starts_at >= now() - interval '30 days'
LEFT JOIN class_enrollments ce ON ce.class_session_id = cs.id
LEFT JOIN bookings bk ON bk.branch_id = b.id
  AND bk.created_at >= now() - interval '30 days'
LEFT JOIN memberships m ON m.tenant_id = b.tenant_id
LEFT JOIN payment_transactions pt ON (pt.booking_id = bk.id OR pt.enrollment_id = ce.id)
GROUP BY b.id, b.tenant_id, b.business_id, b.name
WITH DATA;

CREATE UNIQUE INDEX idx_branch_kpis_branch ON branch_kpis (branch_id);
SELECT cron.schedule('refresh-branch-kpis', '*/15 * * * *',
  $$REFRESH MATERIALIZED VIEW CONCURRENTLY branch_kpis$$);
```

### Class Schedule & Enrollment

```
GET /functions/v1/class-schedule
Auth: bearer
Description: Get class sessions for a branch/date range with enrollment counts

Request (query): branch_id=uuid&date_from=2026-08-01&date_to=2026-08-07&class_type=hiit

Response 200:
{
  "sessions": [{
    "id": uuid,
    "class_type": { "name": string, "difficulty": string },
    "trainer": { "full_name": string, "rating": number },
    "starts_at": string,
    "ends_at": string,
    "spots_remaining": number,
    "is_enrolled": boolean
  }]
}
```

```
POST /functions/v1/enroll-class
Auth: bearer
Description: Enroll member in a group class (capacity-checked atomically)

Request:
{ "class_session_id": uuid, "payment_type": "membership" | "class_pack" | "drop_in" }

Process:
1. Check membership or class_pack credits
2. SELECT enrolled_count FROM class_sessions WHERE id = :id FOR UPDATE
3. If enrolled_count >= max_capacity → 409 class_full
4. INSERT class_enrollments; UPDATE enrolled_count (single transaction)
5. Deduct 1 credit from class_pack if applicable
6. Enqueue SMS confirmation

Response 200: { "success": true, "enrollment_id": uuid, "credits_remaining": number }
Errors: 409 (class full), 403 (no active membership/credits), 422 (already enrolled)
```

```
DELETE /functions/v1/class-enrollments/:id
Auth: bearer
Description: Cancel class enrollment; deduct credit if < 2h notice

Process:
1. Check hours until class start
2. If < 2h: SET status='cancelled'; deduct 1 credit from class_pack; increment no_show_count if 3+ → set require_prepayment
3. If >= 2h: SET status='cancelled'; no credit penalty
4. trigger decrement_class_count_on_cancel fires
5. Waitlist notified via automation_jobs

Response 200: { "success": true, "credit_deducted": boolean }
```

### Check-In

```
POST /functions/v1/check-in
Auth: bearer (reception staff or branch_manager role)
Description: Process QR code scan at gym gate

Request: { "check_in_code": uuid, "branch_id": uuid }

Process:
1. Find member_profiles WHERE check_in_code = :code
2. Find active class_enrollment for today at this branch, or active PT booking
3. Update enrollment/booking status → checked_in
4. INSERT check_ins row
5. Push notification to member: "Welcome to FitBook Lekki! Your HIIT class starts in 12 min"

Response 200:
{
  "success": true,
  "member_name": string,
  "class_or_session": string,
```

### Webhooks

```
POST /functions/v1/webhooks/paystack
Auth: x-paystack-signature (HMAC-SHA512)
Description: Handle charge.success, subscription.create, charge.failed

Process:
1. Verify HMAC: SHA512(body, PAYSTACK_SECRET_KEY) === header
2. Log raw_payload to webhook_logs (before any state mutation)
3. Idempotency key: 'paystack-{event.data.id}'
4. charge.success → confirm booking/enrollment; credit loyalty points (1 pt/₦100)
5. subscription.create → activate membership; SMS welcome
6. charge.failed → release held booking; notify member

Response 200: { "received": true }
Errors: 401 (HMAC mismatch)
```

## SECTION 7 — Automation Engine

### 7.1 Event Catalogue

| Event Name | Trigger | Handler Action | Idempotency Key |
|---|---|---|---|
| `enrollment.confirmed` | Successful class enrollment | SMS: "Enrolled in HIIT Thu 6am at Lekki. Reply CANCEL to withdraw (free until 4am)" | `enroll-{enrollment-id}-confirmed` |
| `booking.held` | PT session hold created | Start 15-min hold timer; log audit | `booking-{id}-held` |
| `booking.confirmed` | PT deposit paid | SMS to member + trainer; push notification; clear held_until | `booking-{id}-confirmed` |
| `booking.checked_in` | Trainer marks checked_in | Log check-in time; notify trainer; start SLA | `booking-{id}-checkin` |
| `booking.completed` | Trainer marks PT session done | Charge balance; credit FitPoints; credit trainer wallet; enqueue rating SMS (30min delay) | `booking-{id}-completed` |
| `booking.cancelled` | PT booking cancelled | Evaluate refund per policy; notify waitlist | `booking-{id}-cancelled` |
| `booking.no_show` | pg_cron 30min post-start, no check-in | Increment member no_show_count; apply no_show_policy | `booking-{id}-no-show` |
| `enrollment.no_show` | pg_cron class end + no check-in | Deduct 1 credit (< 2h cancellation penalty); increment no_show_count if 3+ | `enroll-{id}-no-show` |
| `payment.confirmed` | Paystack webhook charge.success | Update payment_transactions; activate membership/credits | `paystack-{event-id}` |
| `payment.failed` | Paystack webhook charge.failed | Release held booking; SMS retry link | `paystack-{event-id}-fail` |
| `subscription.renewed` | Paystack subscription charge | Extend memberships.ends_at by 1 month; SMS receipt | `paystack-sub-{event-id}` |
| `waitlist.notified` | Enrollment cancelled; spot available | SMS to next waitlist member; 15-min claim window | `waitlist-{entry-id}-notify` |
| `loyalty.credited` | booking.completed or enrollment.completed | Insert loyalty_transactions; check tier threshold; SMS if tier upgraded | `loyalty-{booking-id}-earn` |
| `reminder.2h` | pg_cron 2h before class starts_at | SMS: "Class in 2 hours: HIIT at FitBook Lekki 6am. Reply CANCEL to withdraw (last chance)" | `reminder-{enrollment-id}-2h` |
| `reminder.24h` | pg_cron 24h before PT session | SMS: "PT with Trainer Seun tomorrow 8am. Deposit confirmed" | `reminder-{booking-id}-24h` |
| `pack.expiry_warning` | pg_cron daily 09:00 | Find packs expiring in ≤ 3 days; SMS: "Your 10-class pack expires in 3 days — 4 credits left" | `pack-expire-{membership-id}-{date}` |
| `ai.class_recommendation` | 7 days after last class | Push + SMS: "You haven't been to HIIT in 7 days. Thursday 6am has 5 spots — book now?" | `rebook-{member-id}-{class-type}` |

### 7.2 Cron Jobs

| Job | Schedule | Purpose |
|---|---|---|
| `process_pending_jobs` | every 1 minute | Poll automation_jobs; execute and mark complete/failed |
| `expire_held_pt_bookings` | every 5 minutes | Cancel PT bookings where held_until < now() and status='held' |
| `check_class_no_shows` | every 30 minutes | Find classes that ended >30min ago; mark absent enrollments as no_show |
| `check_pt_no_shows` | every 15 minutes | Find PT sessions past start+30min with no check-in |
| `send_class_reminders` | every 15 minutes | Enqueue 2h and 24h reminder SMS for enrollments and PT bookings |
| `refresh_branch_kpis` | every 15 minutes | REFRESH MATERIALIZED VIEW CONCURRENTLY branch_kpis |
| `batch_trainer_payouts` | daily 08:00 | Calculate completed PT session payouts; credit trainer wallets |
| `pack_expiry_warnings` | daily 09:00 | Find class packs expiring in ≤ 3 days; send SMS |
| `ai_class_recommendations` | daily 10:00 | Find members inactive ≥ 7 days; send class nudge |

### 7.3 Webhook Security

Every Paystack webhook:
1. Read `x-paystack-signature` header
2. Compute HMAC-SHA512 of raw request body using `PAYSTACK_SECRET_KEY`
3. Constant-time comparison to prevent timing attacks
4. Return 200 immediately; enqueue async job
5. Idempotency key: `paystack-{data.id}`; skip if already processed
6. Log full raw_payload to `webhook_logs` before any state mutation

3. Run SQL: `supabase/migrations/0001_fitbook_initial.sql`

5. Paystack: Settings → Webhooks → add `https://[ref].supabase.co/functions/v1/webhooks/paystack`
6. Clone repo: `git clone https://github.com/your-org/fitbook.git && cd fitbook`
7. `npm install`
8. `cp .env.example .env` → fill in all values
9. `supabase functions deploy --project-ref [ref]`
10. `vercel --prod` from `apps/web/`
11. `eas build --platform android --profile production`
