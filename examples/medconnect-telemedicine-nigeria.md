# MedConnect — Telemedicine & Clinical Appointment Platform (Nigeria)

> Generated by the Kajola skill · Nigeria · Paystack · Termii · SORF full lifecycle

**Prompt used:**
> Design a telemedicine and in-clinic appointment booking platform for Nigeria called MedConnect. Patients book video consultations or in-person visits with licensed GPs, dermatologists, cardiologists, and pediatricians. Doctors set their own weekly availability windows. Patients pay a ₦3,000–₦15,000 consultation deposit via Paystack before the slot is confirmed. VIP wellness members get priority booking and earn wellness points per consultation. No-show policy applies after 3 missed appointments (prepayment required). Multi-specialty clinic groups can manage multiple branches and doctors under one account. Full system architecture.

---

## Assumptions Made

- Primary market: Nigeria (NGN); all monetary amounts in Naira
- Authentication: Phone OTP via Termii; no email required
- Payment: Paystack for NGN deposits and balance collection
- Video consultations: Whereby embedded video (per-session room, no SDK installation)
- Appointment types: `video` (teleconsultation) and `in_person`
- Deposit: 50% of consultation fee; refundable with ≥24h cancellation notice
- No-show policy: ≥3 no-shows triggers `require_prepayment = true` on patient profile
- Loyalty: 1 wellness point per ₦100 consultation fee paid; 100 points = 1 free follow-up
- Loyalty tiers: Bronze (0–499 pts), Silver (500–1,999 pts), Gold (2,000+ pts)
- Multi-tenant: each clinic group is a separate tenant; single-doctor practices are a tenant of one branch
- SORF 9-state booking lifecycle applied end-to-end
- Stack: Next.js 14 + Expo 51 + Supabase + Paystack + Termii + Whereby

### 2.3 Data Flow Narratives

**Flow 1 — Patient phone OTP registration**
1. Patient enters `+2348012345678` on Expo app
2. App calls Edge Function `POST /send-otp` → Termii `send-otp` API creates 6-digit OTP, stored hashed in `phone_otps`
3. Patient enters OTP → app calls Supabase Auth `signInWithOtp()` verifying against `phone_otps`
4. Supabase issues JWT with `{ tenant_id, role: 'customer', sub: user_id }`
5. App writes `customer_profiles` row with `full_name`, `preferred_locale: 'en-NG'`
6. Loyalty account created: `loyalty_accounts` row, `points_balance: 0, tier: 'bronze'`

**Flow 2 — Book a consultation (SORF)**
1. Patient searches: `GET /search-doctors?specialty=dermatologist&lat=6.45&lng=3.47`
2. Patient selects Dr. Ngozi, chooses slot from `availability_windows` minus existing `bookings`
3. `POST /book-slot` → insert `bookings` row with `status = held`, `held_until = now() + 15 min`; `EXCLUDE USING gist` enforces no double-booking
4. Frontend shows Paystack popup: ₦5,000 deposit (50% of ₦10,000 dermatology fee)
5. Patient completes payment → Paystack posts webhook to `POST /webhooks/paystack`
6. Edge Function: verify `x-paystack-signature` HMAC → log to `webhook_logs` → update `payment_transactions` → call `POST /confirm-booking`
7. Booking `status → confirmed`; `deposit_paid = true`; Termii SMS sent to patient + doctor
8. `loyalty.credited` job enqueued: `10,000 kobo / 100 = 100 wellness points` credited on completion

**Flow 3 — Video consultation**
1. At appointment time, patient taps "Join Consultation" on app
2. `POST /join-video` → Whereby API creates room `{ roomUrl, hostRoomUrl }`
3. Patient receives `roomUrl`; doctor receives `hostRoomUrl` via push + SMS
4. Whereby embedded WebView launched in-app; consultation proceeds
5. Doctor taps "Mark Complete" on web dashboard → `PATCH /bookings/:id { status: 'completed' }`
6. `booking.completed` event: initiate balance Paystack charge (remaining 50%); enqueue loyalty credit; enqueue rating SMS (30-min delay)

**Flow 4 — Cancellation and waitlist notification**
1. Patient cancels: `PATCH /bookings/:id { status: 'cancelled' }`
2. DB trigger `notify_waitlist_on_cancellation` fires → inserts `automation_jobs` row `job_type: 'waitlist.notify'`
3. `process_pending_jobs` cron picks up job → finds top `waitlist_entries` matching `(branch_id, service_id, staff_id)`
4. Termii SMS: "A slot has opened with Dr. Ngozi on Thursday 2pm. Reply YES to book (valid 15 min)"
5. Patient replies YES → `POST /claim-waitlist-slot` → new booking in `held` state → Paystack deposit flow resumes

-- Increment no-show count when booking status → no_show
CREATE OR REPLACE FUNCTION track_no_show()
RETURNS trigger AS $$
BEGIN
  IF NEW.status = 'no_show' AND OLD.status != 'no_show' THEN
    UPDATE customer_profiles
    SET
      no_show_count = no_show_count + 1,
      require_prepayment = (no_show_count + 1 >= 3)
    WHERE user_id = NEW.customer_id AND tenant_id = NEW.tenant_id;
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_bookings_track_no_show
  AFTER UPDATE OF status ON bookings
  FOR EACH ROW EXECUTE FUNCTION track_no_show();

CREATE OR REPLACE FUNCTION notify_waitlist_on_cancellation()
RETURNS trigger AS $$
BEGIN
  IF NEW.status IN ('cancelled', 'no_show') AND OLD.status NOT IN ('cancelled', 'no_show') THEN
    INSERT INTO automation_jobs (job_type, payload, idempotency_key)
    VALUES (
      'waitlist.notify',
      jsonb_build_object('branch_id', NEW.branch_id, 'service_id', NEW.service_id,
                         'staff_id', NEW.staff_id, 'starts_at', NEW.starts_at),
      'waitlist-' || NEW.branch_id || '-' || NEW.service_id || '-' || NEW.starts_at
    )
    ON CONFLICT (idempotency_key) DO NOTHING;
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE MATERIALIZED VIEW branch_kpis AS
SELECT
  b.id                                                            AS branch_id,
  b.tenant_id,
  b.business_id,
  b.name                                                          AS branch_name,
  count(bk.id)                                                    AS total_bookings_30d,
  count(bk.id) FILTER (WHERE bk.status = 'completed')            AS completed_30d,
  count(bk.id) FILTER (WHERE bk.status = 'no_show')              AS no_shows_30d,
  coalesce(sum(pt.amount_kobo) FILTER (WHERE pt.status = 'paid'), 0) AS gmv_kobo_30d,
  round(avg(r.rating), 2)                                         AS avg_rating
FROM branches b
LEFT JOIN bookings bk ON bk.branch_id = b.id
  AND bk.created_at >= now() - interval '30 days'
LEFT JOIN payment_transactions pt ON pt.booking_id = bk.id
LEFT JOIN reviews r ON r.booking_id = bk.id
GROUP BY b.id, b.tenant_id, b.business_id, b.name
WITH DATA;

CREATE UNIQUE INDEX idx_branch_kpis_branch ON branch_kpis (branch_id);
SELECT cron.schedule('refresh-branch-kpis', '*/15 * * * *',
  $$REFRESH MATERIALIZED VIEW CONCURRENTLY branch_kpis$$);

## SECTION 4 — API Definitions

### Auth

```
POST /functions/v1/send-otp
Auth: none
Description: Initiate phone OTP via Termii; create hashed OTP in phone_otps

Request:
{ "phone": string }  // E.164 format: +2348012345678

Response 200:
{ "success": true, "expires_in": 300 }

Errors:
- 400: Phone number format invalid
- 429: Rate limit: 3 OTPs per phone per 10 minutes
```

```
POST /functions/v1/verify-otp
Auth: none
Description: Verify OTP, mark phone_otps.verified = true, issue Supabase session

Request:
{ "phone": string, "otp": string }

Response 200:
{ "success": true, "access_token": string, "refresh_token": string }

Errors:
- 400: OTP invalid or expired
- 429: 5 incorrect attempts — phone locked 15 minutes
```

### Doctor Discovery

```
GET /functions/v1/search-doctors
Auth: bearer
Description: Search licensed doctors by specialty, location, and availability

Request (query params):
specialty=dermatologist&lat=6.45&lng=3.47&radius_km=10&date=2026-08-01

Response 200:
{
  "doctors": [{
    "id": uuid,
    "full_name": string,
    "specialty": string,
    "rating": number,
    "review_count": number,
    "consultation_fee_kobo": number,
    "offers_video": boolean,
    "offers_inperson": boolean,
    "distance_km": number,
    "next_available_slot": string  // ISO 8601
  }]
}

Errors:
- 400: lat/lng invalid or specialty not in enum
```

### Booking Flow

```
POST /functions/v1/book-slot
Auth: bearer
Description: Create booking in SORF 'held' state (optimistic 15-min lock)

Request:
{
  "staff_id": uuid,
  "service_id": uuid,
  "branch_id": uuid,
  "starts_at": string,           // ISO 8601
  "appointment_type": "video" | "in_person",
  "patient_notes": string
}

Response 200:
{
  "success": true,
  "booking_id": uuid,
  "held_until": string,          // 15 min from now
  "deposit_amount_kobo": number,
  "paystack_init_url": string    // redirect patient to Paystack payment page
}

Errors:
- 409: Slot already taken (EXCLUDE gist violation)
- 403: Customer require_prepayment=true — full amount required
- 422: Slot outside doctor availability_windows
```

```
POST /functions/v1/webhooks/paystack
Auth: x-paystack-signature (HMAC-SHA512)
Description: Handle Paystack charge.success and charge.failed events

Process:
1. Verify HMAC: crypto.subtle.verify(HMAC-SHA512, PAYSTACK_SECRET_KEY, signature, body)
2. Log raw_payload to webhook_logs (before any processing)
3. Check idempotency_key = 'paystack-{event.id}'; skip if already processed
4. On charge.success: update payment_transactions.status='paid'; call confirm-booking
5. On charge.failed: update booking status='cancelled'; notify patient via SMS

Response 200: { "received": true }

Errors:
- 401: HMAC signature mismatch — reject and log
```

```
PATCH /functions/v1/bookings/:id/status
Auth: bearer (doctor or admin role only)
Description: Doctor progresses booking through SORF state machine

Request:
{ "status": "checked_in" | "in_progress" | "completed" | "no_show" | "disputed" }

Allowed transitions:
  confirmed  → checked_in
  checked_in → in_progress | no_show
  in_progress → completed | disputed

Response 200:
{ "success": true, "booking": { ...updated booking } }

Errors:
- 409: Transition not allowed from current status
- 403: Actor not assigned doctor or branch_manager for this booking
```

### Loyalty

```
POST /functions/v1/credit-loyalty
Auth: service role (called internally on booking.completed)
Description: Credit wellness points; idempotent; upgrade tier if threshold crossed

Request:
{ "booking_id": uuid, "customer_id": uuid, "amount_paid_kobo": number }

Points formula: floor(amount_paid_kobo / 10000)  // 1 point per ₦100

Idempotency key: loyalty-{booking_id}-earn
Tier thresholds: Bronze 0–499, Silver 500–1999, Gold 2000+

Response 200:
{ "success": true, "points_credited": number, "new_balance": number, "tier_upgraded": boolean }
```

  }]
}

## SECTION 7 — Automation Engine

### 7.1 Event Catalogue

| Event Name | Trigger | Handler Action | Idempotency Key |
|---|---|---|---|
| `booking.held` | Patient completes book-slot | Start 15-min hold timer; log audit entry | `booking-{id}-held` |
| `booking.confirmed` | Paystack charge.success webhook | SMS to patient + doctor; push notification; clear held_until | `booking-{id}-confirmed` |
| `booking.checked_in` | Doctor marks checked_in | Log check-in time; push to patient "Doctor is ready"; start SLA clock | `booking-{id}-checkin` |
| `booking.completed` | Doctor marks completed | Initiate balance Paystack charge; credit wellness points; enqueue rating SMS (30-min delay); credit doctor wallet | `booking-{id}-completed` |
| `booking.cancelled` | Patient or doctor cancels | Evaluate refund (≥24h = full refund; <24h = forfeit deposit); notify waitlist; update no-show count if applicable | `booking-{id}-cancelled` |
| `booking.no_show` | pg_cron 30+ min post-start, no check-in | Increment patient no_show_count; apply no_show_policy; notify branch manager; enqueue no-show fee if applicable | `booking-{id}-no-show` |
| `booking.disputed` | Doctor or admin raises dispute | Freeze wallet payout; create dispute record; notify clinic admin | `booking-{id}-disputed` |
| `payment.confirmed` | Paystack charge.success | Update payment_transactions.status; update booking deposit_paid | `paystack-{event.id}` |
| `payment.failed` | Paystack charge.failed | Release held booking; notify patient with Paystack retry link | `paystack-{event.id}-fail` |
| `waitlist.notified` | DB trigger on cancellation | SMS to next waitlist patient; set 15-min acceptance window | `waitlist-{entry-id}-notify` |
| `loyalty.credited` | booking.completed | Insert loyalty_transactions; check tier threshold; send tier-upgrade SMS if promoted | `loyalty-{booking-id}-earn` |
| `reminder.24h` | pg_cron 24h before starts_at | Termii SMS: "Your appointment with Dr. {name} is tomorrow at {time}, {branch}" | `reminder-{booking-id}-24h` |
| `reminder.2h` | pg_cron 2h before starts_at | Termii SMS: "Appointment in 2 hours. {whereby_room_url or branch address}" | `reminder-{booking-id}-2h` |
| `ai.noshow_risk` | Daily cron at 22:00 | Score next-day bookings; flag risk > 60%; SMS alert to branch manager | `ai-noshow-{date}-{booking-id}` |
| `ai.rebook_nudge` | 90 days after last completed booking | WhatsApp: "Time for your follow-up with Dr. {name}" | `rebook-{customer-id}-{doctor-id}` |
| `video.room_created` | join-video called | Log Whereby room_url to booking; notify doctor via push | `video-{booking-id}-room` |

### 7.3 Retry Logic

- Attempt 2: +5 minutes
- Attempt 3: +30 minutes
- After max_attempts=3: status = 'dead'; Slack alert to MedConnect ops

### 7.5 Webhook Security

Every Paystack webhook handler:
1. Reads `x-paystack-signature` header
2. Computes HMAC-SHA512 of raw request body using `PAYSTACK_SECRET_KEY`
3. Compares signatures using constant-time comparison
4. Returns 200 immediately; enqueues async job for processing
5. Idempotency key: `paystack-{data.id}`; skips if already processed
6. Logs full raw_payload to `webhook_logs` before any state mutation
